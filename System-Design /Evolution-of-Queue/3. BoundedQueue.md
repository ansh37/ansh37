# Stage 3: The System Protector (Bounded Queue & Backpressure)

## Overview
An unbounded queue will eventually consume all system memory (OOM crash) if producers generate data faster than consumers can process it. A Bounded Queue introduces **Backpressure**—putting producers to sleep when the queue reaches a strict capacity limit. 

This implementation also introduces **Graceful Shutdown** mechanics, allowing the queue to be flushed and safely terminating blocked threads during a system SIGTERM.

## Functional Requirements
* **Capacity Limit:** The queue must not exceed `N` items.
* **Producer Blocking:** If the queue is full, `enqueue` must block until space is freed.
* **Consumer Blocking:** If the queue is empty, `dequeue` must block until data arrives.
* **Graceful Termination:** A `stopAll` mechanism must wake up all sleeping threads and safely reject new operations.

## Architecture: The Out-Parameter Pattern vs. RVO

In Stage 2, we returned values using Return Value Optimization (RVO). Here, we demonstrate the **Out-Parameter Pattern**, heavily used in High-Frequency Trading and game engines.

| Feature | Return By Value (RVO) `T dequeue()` | Out-Parameter `bool dequeue(T& out)` |
| :--- | :--- | :--- |
| **Error Handling** | Requires returning `std::optional<T>` or throwing exceptions. | Returns a `bool` (Success/Fail) or Enum. Cleanest way to handle shutdowns. |
| **Memory Control** | The function creates the object and gives it to the caller. | The Caller pre-allocates the memory exactly where they want it. |
| **Performance** | Extremely fast (compiler optimizes away copies). | Extremely fast (direct memory move into caller's pre-allocated space). |

## Implementation: C++17

```cpp
#include <condition_variable>
#include <queue>
#include <mutex>
#include <iostream>

template <typename T>
class ThreadSafeBoundedQueue {
private:
    mutable std::mutex mtx;
    std::condition_variable not_empty;
    std::condition_variable not_full;
    
    size_t capacity;
    std::queue<T> q;
    bool isFinished;

public:
    // 'explicit' prevents accidental type conversions (e.g., Queue q = 10)
    // Initializer list sets up primitives before constructor body
    explicit ThreadSafeBoundedQueue(size_t n) : capacity(n), isFinished(false) {} 
    
    // Returns true if successfully enqueued, false if queue is shutting down
    bool enqueue(const T& task) {
        std::unique_lock<std::mutex> lock(mtx);
        
        // Sleep if queue is full, UNLESS we are shutting down
        not_full.wait(lock, [this]() { 
            return (q.size() < capacity) || isFinished; 
        });

        if (isFinished) {
            return false; // Safely reject without throwing expensive exceptions
        }

        q.push(task);
        
        // Wake up one sleeping consumer
        not_empty.notify_one(); 
        return true;
    }

    // Returns true if successfully dequeued, false if queue is closed & empty
    bool dequeue(T& out_item) {
        std::unique_lock<std::mutex> lock(mtx);
    
        // Sleep if queue is empty, UNLESS we are shutting down
        not_empty.wait(lock, [this]() { 
            return !q.empty() || isFinished; 
        });

        // If shutdown was called AND the queue is completely drained, exit safely
        if (isFinished && q.empty()) {
            return false;
        }

        // Steal the memory pointers from the queue item into the caller's reference
        out_item = std::move(q.front()); 
        q.pop();
        
        // Wake up one sleeping producer
        not_full.notify_one(); 
        return true;
    }

    // Gracefully wake all threads and close the queue
    void stopAll() {
        std::lock_guard<std::mutex> lock(mtx);
        if (isFinished) return;
        
        isFinished = true;
        
        // Wake up everyone. Producers will return false, Consumers will drain remaining items.
        not_empty.notify_all();
        not_full.notify_all();
    }
    
    size_t size() const {
        std::lock_guard<std::mutex> lock(mtx);
        return q.size();
    }
};
```

## Python Code
*Note: Python does not have C++ style pass-by-reference Out-Parameters. To mimic the C++ error-handling pattern without throwing exceptions, `dequeue` returns a Tuple: `(success_bool, item)`.*

```python
import threading
from collections import deque
from typing import TypeVar, Generic, Optional, Tuple

T = TypeVar('T')

class BoundedThreadSafeQueue(Generic[T]):
    def __init__(self, capacity: int) -> None:
        self.capacity = capacity
        self._container: deque[T] = deque()
        self._condition = threading.Condition()
        self._is_finished = False

    def enqueue(self, item: T) -> bool:
        """Returns True if enqueued, False if the queue is shutting down."""
        with self._condition:
            # Sleep if full. Wake up if space frees up OR if shutting down.
            while len(self._container) >= self.capacity and not self._is_finished:
                self._condition.wait()

            if self._is_finished:
                return False

            self._container.append(item)
            self._condition.notify() # Wake up one sleeping consumer
            return True

    def dequeue(self) -> Tuple[bool, Optional[T]]:
        """Returns (True, item) if successful, (False, None) if shutting down & empty."""
        with self._condition:
            # Sleep if empty. Wake up if data arrives OR if shutting down.
            while not self._container and not self._is_finished:
                self._condition.wait()

            # If shutdown was called and queue is drained, exit safely
            if self._is_finished and not self._container:
                return False, None

            item = self._container.popleft()
            self._condition.notify() # Wake up one sleeping producer
            return True, item

    def stop_all(self) -> None:
        """Gracefully wake all threads and close the queue."""
        with self._condition:
            if self._is_finished:
                return
            
            self._is_finished = True
            self._condition.notify_all() # Wake everyone up to check the flag
            
    def size(self) -> int:
        with self._condition:
            return len(self._container)
```

##TL;DR
## Architectural Decision Record: RVO vs. Out-Parameter

When pulling data out of a queue, C++ offers two primary memory management patterns. Both are extremely fast and avoid deep copies, but they serve different architectural goals.

### The Comparison

| Feature | Return By Value (RVO) | Out-Parameter Pattern |
| :--- | :--- | :--- |
| **Syntax Example** | `T data = q.dequeue();` | `bool success = q.dequeue(data);` |
| **Immutability** | **Pro:** Caller can declare the result as `const`. | **Con:** Caller must create a mutable variable first. |
| **Code Readability** | **Pro:** Clean. Allows function chaining (e.g., `process(q.dequeue())`). | **Con:** Verbose. Requires multiple lines of setup for every call. |
| **Error Handling** | **Con:** Must return `std::optional` (adds branching) or throw exceptions (slow). | **Pro:** Frees the return type to be a `bool` or `enum` for fast, clean error checking. |
| **Memory Control** | **Con:** The function creates the object and hands it to the caller. | **Pro:** The caller pre-allocates the memory exactly where they want it (e.g., in a custom memory arena). |
| **Modern Standard** | **Default:** Strongly preferred in modern C++ (C++14/17+). | **Niche:** Preferred in legacy C++03, embedded systems, or game engines. |

### Which is better?
- For modern, greenfield C++ projects, **Return by Value (RVO) is the gold standard and should be used 95% of the time.** The compiler optimizations are flawless, and it enforces functional immutability (`const` correctness).
- Only reach for the **Out-Parameter** pattern if building ultra-low latency systems (like High-Frequency Trading or Game Engines) where we need to force data directly into pre-warmed, custom memory addresses, or if you need to gracefully handle shutdowns without using C++ exceptions.

*(Note: With the introduction of `std::expected` in C++23, we can now return both a value and an error state perfectly, largely making Out-Parameters obsolete for error handling).*
